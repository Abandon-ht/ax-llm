## 6. 根因分析

### 6.1 直接原因
L3 step 0 发散的直接原因是 **CP 输出的 `codec_sum` 不一致**，进而导致 Talker decode 的 `inputs_embeds` 不一致。

### 6.2 深层原因
`codec_sum` 不一致的根源是 **CP 输入 `last_hidden` 的微小差异**（cos=0.9999958, max_diff=0.5）。该差异来源于：

- **C++**: `all_prefill_hidden` 经 `rmsnorm_bf16()` 逐 token 归一化
- **Python**: `hidden_states = self.norm(hidden)` (PyTorch RMSNorm)

虽然差异极小（mean_diff=0.0086），但 CP 的 5 层 Transformer 将其放大为 `codec_sum` 的显著差异（cos=0.9775），并最终导致 Talker decode 链完全发散。

### 6.3 修复方向

**Option A (推荐)**: 消除 RMSNorm 差异
- 对齐 C++ `rmsnorm_bf16()` 与 PyTorch RMSNorm 的计算精度（gamma 乘法顺序、累加精度、BF16 转换方式）
- 或让 C++ 直接使用 AXModel 中的 RMSNorm 结果作为 `txt_hidden_bf16`，而非自行计算

**Option B**: 在差异可控范围内接受漂移
- 若 0.5 max_diff 的输入差异是硬件/量化固有误差，需评估其对最终音频质量的影响
- 当前 drift 在 CP step 10 才导致 token 分叉，前 9 步完全一致，说明系统具有一定容错能力
